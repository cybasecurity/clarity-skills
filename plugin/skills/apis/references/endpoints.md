# Stacks API endpoint lookup

### Verify the chain and deployment

Endpoint lookup; inspect the response schema in the official API documentation before relying on a field.

| Purpose | Typical endpoint | Evidence/limitations |
|---|---|---|
| Node/chain tip | `GET /v2/info` | Node version, chain identity, current tips; capture retrieval time |
| Epoch/PoX | `GET /v2/pox` | Active PoX contract, epochs and execution limits; check selected tip support |
| Contract source | `GET /v2/contracts/source/{address}/{name}` | Source and publish height; pin `tip` where supported, validate against successful deployment |
| Contract ABI | `GET /v2/contracts/interface/{address}/{name}` | Exact function names/types/access; not behavioral verification |
| Read-only function | `POST /v2/contracts/call-read/{address}/{name}/{function}` | See [read state](../SKILL.md#read-state-and-transactions); does not broadcast |
| Indexed contract metadata | `GET /extended/v3/smart-contracts/{contract_id}` | The successful canonical deployment only: `tx_id`, `clarity_version` and `block`; a failed or missing deployment answers 404 ([query](https://github.com/hirosystems/stacks-blockchain-api/blob/ee0c0ac5bee51b206c67e83e581fab457c34a622/src/datastore/v3/pg-store-v3.ts#L3238-L3279)). `?include=source_code` adds the source; there is no ABI |
| Contract print history | `GET /extended/v2/smart-contracts/{contract_id}/logs` | Cursor pagination, emitter/topic and serialized value; join canonical block/receipt evidence ([historical readers](../SKILL.md#historical-event-readers-and-exports)) |
| Transaction detail | `GET /extended/v3/transactions/{tx_id}?include=function_args,result` | Mined or mempool; require successful mined block evidence; current v3 omits a canonical boolean |
| Transaction events | `GET /extended/v3/transactions/{tx_id}/events` | Independently paginated; fetch every event page, not just the first |
| Account nonce and balance | `GET /v2/accounts/{principal}?proof=0` | Hex `balance`/`locked` and `nonce`; the next nonce from confirmed state only. Mempool-aware nonces: `GET /extended/v3/principals/{address}/nonces` returns `next_nonce`, `last_confirmed_nonce` and `mempool.last_nonce` (current state, standard addresses only). `mempool.pending_nonces` lists only nonces strictly between `last_confirmed_nonce` and `mempool.last_nonce`; to test whether a nonce is taken, compare it with those two ([route](https://github.com/hirosystems/stacks-blockchain-api/blob/ee0c0ac5bee51b206c67e83e581fab457c34a622/src/api/routes/v3/principals.ts#L674-L702), [derivation](https://github.com/hirosystems/stacks-blockchain-api/blob/ee0c0ac5bee51b206c67e83e581fab457c34a622/src/datastore/pg-store.ts#L618-L707)) |
| STX and token balances | `GET /extended/v3/principals/{principal}/balances/stx`, `/balances/ft`, `/balances/nft` | Indexed, current tip only. STX: `balance` and spendable `available` as strings, `locked` (null, or an object with `amount`, `burn_unlock_height` and the lock's `lock_tx_id`) and `mempool` (null when nothing is pending, or `inbound`, `outbound` and `estimated_balance`). FT rows are `{asset_identifier, balance}` in base units and NFT rows one `{asset_identifier, value}` per owned instance, both cursor-paginated; `/balances/ft/{asset_identifier}` returns one token, with a zero balance when none is held ([routes](https://github.com/hirosystems/stacks-blockchain-api/blob/ee0c0ac5bee51b206c67e83e581fab457c34a622/src/api/routes/v3/principals.ts#L482-L672)) |
| Fee estimates | `GET /v2/fees/transfer`, `POST /v2/fees/transaction` | Transfer fee rate in µSTX per byte; the POST estimates a payload |
| Broadcast | `POST /v2/transactions` (raw bytes) | Use `broadcastTransaction` from `@stacks/transactions`; a returned txid is acceptance into the mempool, not inclusion |
| Mempool | `GET /extended/v3/mempool/transactions`, or `GET /extended/v3/principals/{principal}/mempool/transactions` for one principal | Pending transactions only, cursor-paginated; no sender, recipient or ordering filters ([route](https://github.com/hirosystems/stacks-blockchain-api/blob/ee0c0ac5bee51b206c67e83e581fab457c34a622/src/api/routes/v3/mempool.ts#L45-L80)) |
| Fungible-token metadata | `GET /metadata/v1/ft/{contract_id}` | Name, symbol, decimals as indexed; confirm against the contract's own read-only functions |
| Nakamoto blocks | `GET /extended/v3/blocks`, `/extended/v3/blocks/{height_or_hash}` (height, hash, index hash or `latest`; API 9.7.0 or later) | `index_hash`, `tenure_height` and `bitcoin_block.height` ([routes](https://github.com/hirosystems/stacks-blockchain-api/blob/01661c242a8aea92ba44b6302cacef4369681d94/src/api/routes/v3/blocks.ts#L26-L88)); distinguish Stacks, tenure and burnchain heights |

- Every `/extended/v1` REST data route is deprecated. Its responses carry `Warning: 299`, and once Hiro turns deprecated routes off they return 410 Gone ([switch](https://github.com/hirosystems/stacks-blockchain-api/blob/ee0c0ac5bee51b206c67e83e581fab457c34a622/src/api/deprecation-plugin.ts#L18-L47)). Hiro's [v1 to v3 migration guide](https://docs.hiro.so/en/apis/stacks-blockchain-api/v1-to-v3-migration) maps each route and field.
- v3 is a redesign, not a rename. Lists take `limit` and `cursor`, not `offset`, and return summaries; the transaction and mempool lists have no server-side filters. Fields are renamed or nested: `tx_status` is `status`, `sender_address` is `sender.address`, `block_height` is `block.height`. Only canonical data comes back, so there is no `canonical` field.
- Six v2 routes are deprecated but exempt from the sunset ([exemption](https://github.com/hirosystems/stacks-blockchain-api/blob/01661c242a8aea92ba44b6302cacef4369681d94/src/api/routes/v2/blocks.ts#L33-L42)): `/extended/v2/blocks`, `/blocks/{height_or_hash}` and `/blocks/{height_or_hash}/transactions`, and `/extended/v2/burn-blocks`, `/burn-blocks/{height_or_hash}` and `/burn-blocks/{height_or_hash}/blocks`. The v2 address transaction and balance routes are deprecated without the exemption. The other v2 routes are not deprecated: smart-contract `/status` and `/{contract_id}/logs`, average block times, blocks by time, signer signatures, block tenures, mempool fees, PoX cycles and both `pox-transactions` routes.
